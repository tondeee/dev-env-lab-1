## Створені сервіси
1. `data_load`
Читає CSV-файл `marketing_campaign.csv`, створює таблицю `customers` у SQLite та імпортує записи до БД.

2. `data_quality_analysis`
Перевіряє пропуски, дублікати рядків, дублікати `ID` і коректність числових полів. Результат записує у `data_quality_report.json`.

3. `data_research`
Обчислює базові статистики для доходу та витрат, визначає середній дохід, медіану, частку позитивного відгуку та найпоширеніші рівні освіти. Результат записує у `data_research_report.json`.

4. `visualization`
Будує два графіки: гістограму розподілу доходу та діаграму розсіювання витрат на вино і м'ясо. Зберігає їх у PNG.

5. `web`
Flask-застосунок, який відображає головну сторінку, короткий опис проєкту, попередній перегляд даних, результати перевірки якості, результати дослідження та графіки.

## Архітектура та взаємодія контейнерів
Обмін результатами організовано через спільні Docker volumes.

1. `runtime_data`
Містить файл SQLite `analytics.db`.

2. `reports_data`
Містить JSON-звіти від сервісів `data_quality_analysis` і `data_research`.

3. `plots_data`
Містить PNG-графіки від сервісу `visualization`.

4. `analytics_net`
Окрема Docker network, до якої підключені всі сервіси.

Потік виконання:
1. `data_load` імпортує CSV у SQLite.
2. `data_quality_analysis`, `data_research` і `visualization` очікують появу таблиці `customers` у БД.
3. Після появи БД вони створюють звіти та графіки.
4. `web` читає дані з БД та змонтованих volumes і показує результати у браузері.

## Короткий звіт про виконання
### Які сервіси створені
Створено п'ять сервісів: `data_load`, `data_quality_analysis`, `data_research`, `visualization` і `web`.

### Як організовано взаємодію
Основним каналом взаємодії є SQLite база даних у спільному volume. Додатково JSON-звіти та PNG-графіки зберігаються у окремих volumes, які читає веб-сервіс.

### Які труднощі виникли
1. Початковий проєкт містив лише окремі скрипти у `src/`, тому довелося перетворити їх на незалежні контейнерні сервіси.
2. Для надійного запуску кількох контейнерів потрібне очікування готовності БД, тому в спільній бібліотеці реалізовано `wait_for_table`.
3. Для веб-перегляду результатів потрібно було окремо підготувати HTML-шаблон і маршрут для видачі PNG-файлів.

## Відповіді на контрольні питання
1. **Що таке контейнеризація і чим вона відрізняється від віртуалізації?**
Контейнеризація ізолює застосунок на рівні процесів і спільно використовує ядро ОС, тоді як віртуалізація запускає окрему повноцінну гостьову ОС у віртуальній машині. Контейнери легші та стартують швидше.

2. **Для чого використовується Dockerfile?**
`Dockerfile` описує покрокову інструкцію побудови Docker image: базовий образ, залежності, файли, середовище виконання та команду запуску.

3. **Для чого використовується Docker Compose?**
Docker Compose дозволяє описати й одночасно запускати багатоконтейнерний застосунок, включаючи сервіси, мережі, томи, порти та змінні середовища.

4. **Що таке Docker image і Docker container?**
Docker image - це шаблон або знімок застосунку з усім необхідним для запуску. Docker container - це запущений екземпляр image.

5. **Для чого потрібні volumes?**
Volumes потрібні для збереження даних між перезапусками контейнерів і для обміну файлами між сервісами.

6. **Для чого потрібні networks?**
Networks дозволяють контейнерам обмінюватися даними в межах ізольованого середовища та звертатися один до одного за іменами сервісів.

7. **Як організувати взаємодію між контейнерами?**
Через внутрішню мережу, спільні volumes, бази даних, API або черги повідомлень. У цій роботі взаємодія реалізована через SQLite і shared volumes.

8. **Які переваги дає контейнеризація для DevOps-проєктів?**
Вона забезпечує відтворюваність середовища, швидке розгортання, ізоляцію залежностей, простіший CI/CD та зручне масштабування.

9. **Чому веб-інтерфейс варто виділяти в окремий сервіс?**
Це спрощує підтримку, дозволяє незалежно оновлювати UI, відокремлює візуалізацію від обробки даних і зручніше масштабується.

10. **Які проблеми можуть виникати при запуску кількох контейнерів одночасно?**
Типові проблеми: конфлікти портів, невірний порядок запуску, неготовність залежного сервісу, помилки в мережевих налаштуваннях, відсутність volumes або змінних середовища.
