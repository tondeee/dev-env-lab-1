# Звіт з виконання Лабораторної роботи №2

## Тема
Побудова CI/CD-конвеєра із використанням GitHub Actions.

## Мета
Налаштувати автоматизацію процесів тестування, лінтингу та збірки проєкту за допомогою GitHub Actions, а також організувати публікацію результатів аналізу.

## Виконані завдання

### Частина A: CI для кожного модуля
1. **Створення workflow:** Створено файл `.github/workflows/ci.yml`.
2. **Тригери:** Налаштовано запуск пайплайну при:
   - `push` у гілку `main`.
   - `pull_request` у гілку `main`.
   - Ручному запуску (`workflow_dispatch`) з можливістю вибору конкретного модуля (`all`, `data_load`, `data_quality_analysis`, `data_research`, `visualization`).
3. **Матрична стратегія:** Використано `strategy.matrix` для паралельного запуску 4 модулів.
4. **Оптимізація (Bonus):** Додано фільтрацію за шляхами (`dorny/paths-filter`), що дозволяє запускати лише ті модулі, файли яких були змінені.

### Частина B: CD та публікація результатів
1. **Артефакти:** Після кожного успішного виконання модуля результати (логи, звіти) завантажуються як GitHub Actions artifacts (`actions/upload-artifact@v4`).
2. **GitHub Pages (Bonus):** Налаштовано автоматичне розгортання статичного звіту на GitHub Pages після успішного CI в гілці `main`. Звіт включає згенерований графік розподілу доходів (`income_distribution.png`).

### Частина C: Self-hosted runner
1. **Налаштування:** Підключено локальний агент (self-hosted runner) на базі macOS.
2. **Workflow:** Створено окремий файл `.github/workflows/ci-selfhosted.yml` для запуску модуля візуалізації на локальній машині.

## Порівняння GitHub-hosted та Self-hosted runners

| Характеристика | GitHub-hosted Runner | Self-hosted Runner |
|:--- |:--- |:--- |
| **Швидкість** | Залежить від завантаженості хмари GitHub (зазвичай середня). | Залежить від потужності власного ПК (часто швидше для важких задач). |
| **Доступ до ресурсів** | Обмежений (тільки те, що в репозиторії або встановлено через steps). | Повний доступ до локальної файлової системи, GPU, великих датасетів. |
| **Безпека** | Висока (ізольовані віртуальні машини). | Нижча (потребує обережності при роботі з публічними PR, доступ до хоста). |
| **Стабільність** | 99.9% доступності від GitHub. | Залежить від вашого інтернет-з'єднання та стану ПК (може бути offline). |

## Висновки
У ході лабораторної роботи було успішно побудовано повноцінний CI/CD конвеєр. Використання матричних стратегій дозволило значно скоротити час виконання за рахунок паралелізму, а фільтрація шляхів оптимізувала ресурси. Налаштування self-hosted runner показало переваги локального контролю над середовищем виконання, особливо для задач, що потребують доступу до великих локальних даних або специфічного апаратного забезпечення.
